# Herdr 可选第三方工具接入

## 范围

采用已确认的 A 方案：独立「第三方工具」页面，沿用现有界面风格，不改变普通用户的通知流程。基于 v2.15.0 和 PR #35 的贡献者提交在独立分支开发，保留作者归属。本次只交付本地代码、测试结果和 DMG，不合并远程 PR、不推送、不发布 Release。

版本提议为 **2.16.0**（新增可选功能）；随本文确认后统一更新项目及打包元数据。

## UI 与操作

- 侧栏新增「第三方工具」，首次只展示 Herdr 卡片，标注第三方维护、贡献者 8liang 及插件仓库。
- Herdr 默认关闭。页面静态展示说明，不因打开页面自动执行 Herdr 命令。
- 「检查」仅在用户点击后查询依赖和插件状态；「配置」明确说明将安装社区插件并更新桥接路径，用户确认后才执行。不安装 Herdr 主程序。
- 配置成功后仍保持本应用的 Herdr 通知关闭；单独通过「启用 Herdr 通知」开关开启。启用前须确认可能与原生集成重复通知。
- 缺少依赖、配置失败、超时只在卡片内展示，不弹出全局缺失提醒。操作期间防止重复点击，结束后允许重试。
- Herdr 单独使用现有来源配置能力和已启用的通知渠道，不自动修改其他来源或渠道。中英文文案齐全，开关和按钮可用键盘操作。

## 隔离与必要修复

- `sources.herdr.enabled` 默认 false，关闭时通知引擎拒绝该来源，即使插件使用 force 参数也不能绕过。
- 普通启动、watch 和通用 hooks status 不运行 Herdr 外部命令；保留无副作用的 Herdr 能力标记，兼容插件对来源支持的检测。实际安装状态仅通过显式目标查询获取。
- 配置与启用分离，不用安装动作隐式开启本应用通知；既有用户状态不被重新配置无意更改。
- 只更新插件配置中的受管桥接路径，保留其他自定义内容；按 Bash 语义引用路径，覆盖空格、单引号和 shell 元字符场景。不通过 source 执行用户配置来读取内容。
- 打包桥接使用应用自带 Node，不依赖系统 Node；独立通知调用不能继承仅供 Tauri 接收的 stdout 通知模式。复用现有路径与通知实现，不新增插件框架。
- 不改变 Claude、Codex、Gemini、OpenCode hooks、watch、去重键或用户设置。现阶段明确提示重复风险，不承诺跨来源去重。
- 插件依赖 Bash/Python3，界面如实说明依赖和已验证平台，不把 mock 测试称作真实 Windows 或 Herdr 联调。

## 验收与交付

1. 运行现有回归测试及 PR 测试；补充默认关闭、force 不绕过关闭、普通状态不执行 Herdr、显式查询失败隔离的检查。
2. 检查配置保留、路径引用、重复配置及打包运行时桥接；测试数据和临时配置仅写在工作区内，不修改真实用户通知配置。
3. UI 检查中英文、关闭初态、配置后仍关闭、重复风险确认、失败重试及原有页面可用性。
4. 构建后核对应用版本、CPU 架构、签名检查结果及 DMG 可挂载性；保留既有安装窗口布局和 Applications 快捷方式。签名或公证状态如实报告。
5. 本机先交付 Apple Silicon 包 `ai-cli-complete-notify_2.16.0_aarch64.dmg`，不覆盖 2.15.0 文件。Intel 若无法在本地完成构建验证，明确列为未交付，不改名冒充；启用远程 CI 另行确认。
6. 提供 DMG 绝对路径、SHA256、测试结果和未验证事项。没有真实 Herdr 环境时明确说明，仅完成模拟与桥接验证，不安装用户未授权的主程序。

## 自审

范围仅为单个可选接入入口及使其安全可用的必要修复；无新增依赖框架，无自动安装或后台探测，无远程发布。默认关闭、配置与启用分离以及其他来源不受影响为必须通过的验收条件。
